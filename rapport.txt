\section{Introduction}

\subsection{Contexte}
Dans le cadre du TP de Machine Learning, ce projet porte sur la \textbf{classification binaire} appliquée au dataset UCI SECOM. L'objectif est de détecter les produits défectueux dans un processus de fabrication de semi-conducteurs, à partir de 591 capteurs (features).

\subsection{Problématique}
Le dataset présente deux défis majeurs :
\begin{itemize}
    \item \textbf{Déséquilibre sévère des classes} : seulement $\sim$6.6\% des échantillons sont des défauts (classe 1), soit un ratio d'environ 1:14.
    \item \textbf{Forte proportion de valeurs manquantes} : 462 features sur 590 contiennent des NaN, dont 24 avec plus de 50\% de données manquantes.
\end{itemize}

\subsection{Objectifs}
\begin{enumerate}
    \item Comparer 4 modèles de classification : Decision Tree, Random Forest, AdaBoost et Neural Network (MLP).
    \item Gérer le déséquilibre via SMOTE (Synthetic Minority Over-sampling Technique).
    \item Évaluer les modèles avec des métriques adaptées (Recall, AUC, F1) plutôt que l'accuracy.
    \item Implémenter deux approches de splitting pour illustrer les bonnes pratiques.
\end{enumerate}

\section{Description des Données}

\subsection{Le Dataset UCI SECOM}
\begin{itemize}
    \item \textbf{Source} : UCI Machine Learning Repository
    \item \textbf{Échantillons} : 1567 observations
    \item \textbf{Features} : 590 variables numériques issues de capteurs industriels
    \item \textbf{Variable cible} : \texttt{Pass/Fail} $\rightarrow$ recodée en 0 (bon) et 1 (défaut)
    \item \textbf{Colonnes supprimées} : \texttt{Time} et \texttt{Phase} (non informatives)
\end{itemize}

\subsection{Analyse Exploratoire (EDA)}

\subsubsection{Déséquilibre des Classes}

\begin{figure}[H]
    \centering
    \includegraphics[width=0.85\textwidth]{img_eda_distribution.png}
    \caption{Distribution des classes dans le Train Set et pourcentage de NaN par feature}
    \label{fig:eda}

Le Train Set (70\%) contient :
\begin{itemize}
    \item \textbf{Classe 0 (Bon)} : 1023 échantillons (93.3\%)
    \item \textbf{Classe 1 (Défaut)} : 73 échantillons (6.7\%)
    \item \textbf{Ratio d'imbalance} : 1:14
\end{itemize}

Ce déséquilibre rend l'accuracy trompeuse : un classifieur qui prédit toujours ``bon'' obtient 93\% d'accuracy mais ne détecte aucun défaut.

\subsubsection{Valeurs Manquantes}
Sur 590 features :
\begin{itemize}
    \item 462 features contiennent au moins un NaN
    \item 24 features ont plus de 50\% de valeurs manquantes
\end{itemize}
Stratégie retenue : \textbf{imputation par la médiane} (robuste aux outliers).

\section{Méthodologie}

\subsection{Split des Données}
\begin{itemize}
    \item \textbf{Train} : 70\% (1096 échantillons)
    \item \textbf{Test} : 30\% (471 échantillons)
    \item Split \textbf{stratifié} (\texttt{stratify=y}) pour maintenir la proportion de défauts dans les deux sets
    \item \texttt{random\_state=42} pour la reproductibilité
\end{itemize}

\subsection{Pipeline de Prétraitement}
L'ordre des opérations est crucial pour éviter la fuite de données (data leakage) :

\begin{enumerate}
    \item \textbf{Imputation} : \texttt{SimpleImputer(strategy='median')} -- remplace les NaN par la médiane de chaque feature
    \item \textbf{Scaling} : \texttt{StandardScaler()} -- normalisation centrée réduite ($\mu=0$, $\sigma=1$)
    \item \textbf{SMOTE} : sur le Train uniquement -- génère des échantillons synthétiques de la classe minoritaire
\end{enumerate}

\textbf{Règle fondamentale} : le \texttt{fit} se fait exclusivement sur les données d'entraînement. Le Test Set n'est jamais utilisé pour calibrer les transformations.

\subsection{Les Deux Approches Implémentées}

\subsubsection{Approche A -- ImbPipeline (SplitA.ipynb)}
Utilise \texttt{imblearn.pipeline.Pipeline} qui encapsule toute la chaîne (Imputation $\rightarrow$ Scaling $\rightarrow$ SMOTE $\rightarrow$ Modèle) dans un seul objet. Lors de la validation croisée, SMOTE est automatiquement ré-appliqué uniquement sur chaque pli d'entraînement.

\textbf{Avantage} : Garantie zéro leakage, code compact.

\subsubsection{Approche B -- Prétraitement Manuel (SplitB.ipynb)}
Applique chaque étape manuellement : \texttt{fit\_transform} sur le Train, puis \texttt{transform} sur le Test. SMOTE est appliqué une seule fois sur le Train complet avant l'entraînement.

\textbf{Avantage} : Contrôle explicite de chaque étape, plus pédagogique.

\subsection{Métriques d'Évaluation}
Pour un dataset déséquilibré, l'accuracy est inadaptée. Les métriques privilégiées sont :

\begin{itemize}
    \item \textbf{Recall (Sensibilité)} : $\dfrac{VP}{VP + FN}$ -- proportion de défauts correctement détectés. \textit{Prioritaire en contexte industriel}.
    \item \textbf{AUC (ROC)} : aire sous la courbe ROC -- mesure la capacité de discrimination globale du modèle (1.0 = parfait, 0.5 = aléatoire).
    \item \textbf{F1-Score} : $2 \times \dfrac{Precision \times Recall}{Precision + Recall}$ -- moyenne harmonique entre précision et rappel.
\end{itemize}

\subsection{Critère de Sélection du Meilleur Modèle}
Un \textbf{score composite} est utilisé :
$$\text{Score} = 0.4 \times \text{AUC} + 0.3 \times \text{Recall} + 0.3 \times \text{F1}$$

Ce score empêche qu'un modèle avec un bon AUC mais un Recall de 0\% (ne détectant aucun défaut) soit sélectionné comme meilleur modèle. C'est exactement le cas du Random Forest dans ce projet.

\section{Discussion}

\subsection{Pourquoi Random Forest a un bon AUC mais un Recall de 0\% ?}
L'AUC mesure la qualité du \textit{ranking} des probabilités, pas la qualité des prédictions à un seuil donné. Random Forest assigne des probabilités plus élevées aux vrais défauts, mais aucune ne dépasse 0.5. Baisser le seuil à 0.18 permet de récupérer 87\% de Recall.

Cela illustre une leçon fondamentale : \textbf{l'AUC seul ne suffit pas} pour évaluer un modèle sur données déséquilibrées. Il faut toujours examiner le Recall et envisager une optimisation du seuil.

\subsection{Comparaison des Deux Approches (A vs B)}
Les deux approches (ImbPipeline vs Prétraitement Manuel) produisent les \textbf{mêmes résultats numériques} sur le Test Set, ce qui est attendu car elles appliquent les mêmes transformations. La différence se situe dans la \textbf{rigueur de la validation croisée} :

\begin{itemize}
    \item \textbf{Approche A} : SMOTE est ré-appliqué à chaque pli de CV $\rightarrow$ pas de leakage
    \item \textbf{Approche B} : Les scores de CV sont aussi rigoureux car on utilise un ImbPipeline pour la CV, mais le modèle final est entraîné sur des données SMOTE pré-calculées
\end{itemize}

\subsection{Limites et Améliorations Possibles}
\begin{itemize}
    \item \textbf{Feature Selection} : Avec 590 features et seulement 1567 échantillons, une sélection de variables (PCA, importance des features) pourrait améliorer la généralisation.
    \item \textbf{Hyperparameter Tuning} : GridSearchCV ou RandomizedSearchCV sur les hyperparamètres de chaque modèle.
    \item \textbf{Autres techniques de rééchantillonnage} : ADASYN, BorderlineSMOTE, ou sous-échantillonnage de la classe majoritaire.
    \item \textbf{Modèles supplémentaires} : XGBoost, LightGBM, SVM, ou des architectures de deep learning plus profondes.
\end{itemize}

% ══════════════════════════════════════════════════════════════
%                      6. CONCLUSION
% ══════════════════════════════════════════════════════════════
\section{Conclusion}

Ce projet a permis de comparer quatre modèles de classification sur le dataset SECOM, en mettant l'accent sur la gestion rigoureuse du déséquilibre de classes.

\textbf{Résultats clés} :
\begin{itemize}
    \item \textbf{AdaBoost} est le meilleur modèle au seuil par défaut (Score composite = 0.4367), grâce à son meilleur compromis AUC/Recall/F1.
    \item \textbf{Random Forest} a le meilleur potentiel (AUC = 0.83) mais nécessite une optimisation du seuil (0.18 au lieu de 0.5) pour détecter les défauts.
    \item L'utilisation de SMOTE dans un pipeline intégré (ImbPipeline) est la méthode la plus propre pour éviter le data leakage en validation croisée.
    \item Le Recall est la métrique prioritaire en détection de défauts industriels : mieux vaut quelques faux positifs que des défauts non détectés.
\end{itemize}
