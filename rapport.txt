\section{Introduction}

\subsection{Contexte}
Dans le cadre du TP de Machine Learning, ce projet porte sur la \textbf{classification binaire} appliquée au dataset UCI SECOM. L'objectif est de détecter les produits défectueux dans un processus de fabrication de semi-conducteurs, à partir de 591 capteurs (features).

\subsection{Problématique}
Le dataset présente deux défis majeurs :
\begin{itemize}
    \item \textbf{Déséquilibre sévère des classes} : seulement $\sim$6.6\% des échantillons sont des défauts (classe 1), soit un ratio d'environ 1:14.
    \item \textbf{Forte proportion de valeurs manquantes} : 462 features sur 590 contiennent des NaN, dont 24 avec plus de 50\% de données manquantes.
\end{itemize}

\subsection{Objectifs}
\begin{enumerate}
    \item Comparer 4 modèles de classification : Decision Tree, Random Forest, AdaBoost et Neural Network (MLP).
    \item Gérer le déséquilibre via SMOTE (Synthetic Minority Over-sampling Technique).
    \item Évaluer les modèles avec des métriques adaptées (Recall, AUC, F1) plutôt que l'accuracy.
    \item Implémenter deux approches de splitting pour illustrer les bonnes pratiques.
\end{enumerate}

    \item \textbf{Colonnes supprimées} : \texttt{Time} et \texttt{Phase} (non informatives)
\end{itemize}

\subsubsection{Déséquilibre des Classes}

\section{Méthodologie}

\subsection{Split des Données}
\begin{itemize}
    \item \textbf{Train} : 70\% (1096 échantillons)
    \item \textbf{Test} : 30\% (471 échantillons)
    \item Split \textbf{stratifié} (\texttt{stratify=y}) pour maintenir la proportion de défauts dans les deux sets
    \item \texttt{random\_state=42} pour la reproductibilité
\end{itemize}

\subsection{Pipeline de Prétraitement}
L'ordre des opérations est crucial pour éviter la fuite de données (data leakage) :

\begin{enumerate}
    \item \textbf{Imputation} : \texttt{SimpleImputer(strategy='median')} -- remplace les NaN par la médiane de chaque feature
    \item \textbf{Scaling} : \texttt{StandardScaler()} -- normalisation centrée réduite ($\mu=0$, $\sigma=1$)
    \item \textbf{SMOTE} : sur le Train uniquement -- génère des échantillons synthétiques de la classe minoritaire
\end{enumerate}

\textbf{Règle fondamentale} : le \texttt{fit} se fait exclusivement sur les données d'entraînement. Le Test Set n'est jamais utilisé pour calibrer les transformations.

\subsection{Les Deux Approches Implémentées}

L'objectif est de comparer une approche \textbf{correcte} (sans data leakage) et une approche \textbf{incorrecte} (avec data leakage) pour illustrer l'impact de la fuite de données sur les résultats.

\subsubsection{Approche A -- Split AVANT Preprocessing (SplitA.ipynb)}
\textbf{Approche correcte.} Le dataset est d'abord séparé en Train/Test, puis l'imputation et le scaling sont \texttt{fit} uniquement sur le Train. Le Test est transformé avec les paramètres du Train. SMOTE est appliqué uniquement au Train.

Utilise \texttt{imblearn.pipeline.Pipeline} (ImbPipeline) qui encapsule toute la chaîne dans un seul objet, garantissant que chaque pli de validation croisée est traité indépendamment.

\textbf{Avantage} : Zéro data leakage, résultats fiables et généralisables.

\subsubsection{Approche B -- Preprocessing AVANT Split (SplitB.ipynb)}
\textbf{Approche incorrecte (data leakage volontaire).} L'imputation et le scaling sont réalisés sur \textbf{tout} le dataset (Train + Test) \textit{avant} le split. Ainsi, la médiane utilisée pour l'imputation et les paramètres $\mu$/$\sigma$ du StandardScaler sont calculés en incluant les données de test.

Le modèle a donc indirectement ``vu'' le test lors du preprocessing : les statistiques globales (médiane, moyenne, écart-type) sont contaminées par les échantillons du test.

\textbf{Conséquence attendue} : Les résultats peuvent être artificiellement gonflés ou biaisés, car le modèle bénéficie d'informations qu'il ne devrait pas avoir.

\subsection{Métriques d'Évaluation}
Pour un dataset déséquilibré, l'accuracy est inadaptée. Les métriques privilégiées sont :

\begin{itemize}
    \item \textbf{Recall (Sensibilité)} : $\dfrac{VP}{VP + FN}$ -- proportion de défauts correctement détectés. \textit{Prioritaire en contexte industriel}.
    \item \textbf{AUC (ROC)} : aire sous la courbe ROC -- mesure la capacité de discrimination globale du modèle (1.0 = parfait, 0.5 = aléatoire).
    \item \textbf{F1-Score} : $2 \times \dfrac{Precision \times Recall}{Precision + Recall}$ -- moyenne harmonique entre précision et rappel.
\end{itemize}

\subsection{Optimisation des Hyperparamètres}
On utilise \texttt{RandomizedSearchCV} (20 itérations, 5-Fold stratifié, scoring = recall) pour chaque modèle. Cette méthode est préférée à \texttt{GridSearchCV} car avec 590 features, une recherche exhaustive serait prohibitive. Les espaces de recherche incluent :

\begin{itemize}
    \item \textbf{Decision Tree / Random Forest} : profondeur max, min\_samples\_split, min\_samples\_leaf
    \item \textbf{AdaBoost} : nombre d'estimateurs, learning rate
    \item \textbf{Neural Network} : architecture (couches cachées), régularisation ($\alpha$), learning rate
\end{itemize}

\subsection{Critère de Sélection du Meilleur Modèle}
Un \textbf{score composite} est utilisé :
$$\text{Score} = 0.4 \times \text{AUC} + 0.3 \times \text{Recall} + 0.3 \times \text{F1}$$

Ce score empêche qu'un modèle avec un bon AUC mais un Recall de 0\% (ne détectant aucun défaut) soit sélectionné comme meilleur modèle. C'est exactement le cas du Random Forest dans ce projet.

\section{Discussion}

\subsection{Pourquoi Random Forest a un bon AUC mais un Recall de 0\% ?}
L'AUC mesure la qualité du \textit{ranking} des probabilités, pas la qualité des prédictions à un seuil donné. Random Forest assigne des probabilités plus élevées aux vrais défauts, mais aucune ne dépasse 0.5. Baisser le seuil à 0.18 permet de récupérer 87\% de Recall.

Cela illustre une leçon fondamentale : \textbf{l'AUC seul ne suffit pas} pour évaluer un modèle sur données déséquilibrées. Il faut toujours examiner le Recall et envisager une optimisation du seuil.

\subsection{Impact du Data Leakage (Approche A vs B)}
Le data leakage se produit lorsque des informations du test set ``fuient'' dans le processus d'entraînement. Dans l'Approche B, la médiane d'imputation et les paramètres de scaling ($\mu$, $\sigma$) sont calculés sur \textbf{tout} le dataset, incluant le test.

\textbf{Conséquences observées} :
\begin{itemize}
    \item Les scores composites de l'Approche B sont légèrement biaisés par rapport à l'Approche A.
    \item AdaBoost obtient un score composite de 0.4739 (B) contre 0.4367 (A), soit une surestimation de \textbf{+8.5\%}.
    \item Decision Tree passe de 0.3610 (A) à 0.3944 (B), soit \textbf{+9.3\%} de surestimation.
    \item Ces différences, bien que modestes sur ce dataset, peuvent être \textbf{beaucoup plus importantes} sur des datasets plus petits ou avec des features plus corrélées.
\end{itemize}

\textbf{Leçon pédagogique} : Même si la fuite semble ``inoffensive'' (juste des médianes et des moyennes), elle biaise l'évaluation du modèle. En production, les performances réelles seront toujours inférieures à celles mesurées avec leakage. L'Approche A (split avant preprocessing) est la \textbf{seule méthode correcte}.

\subsection{Analyse des Compromis (Trade-offs)}

Ce projet met en lumière trois compromis fondamentaux en ML :

\begin{enumerate}
    \item \textbf{Recall vs Précision} : Augmenter le Recall (via SMOTE, seuil bas) augmente les faux positifs. En industrie, un faux positif (pièce bonne rejetée) coûte moins cher qu'un faux négatif (défaut non détecté).
    \item \textbf{Performance vs Complexité} : AdaBoost (modèle simple, 50 estimateurs) surpasse le Neural Network (modèle complexe, 2 couches). Sur des datasets petits (1567 échantillons), la parcimonie l'emporte.
    \item \textbf{Robustesse vs Surapprentissage} : Le tuning améliore le Recall (+150\% pour AdaBoost) mais peut réduire légèrement l'AUC. Le learning rate faible (0.04) rend le modèle plus robuste en ralentissant la convergence.
\end{enumerate}

\subsection{Limites et Améliorations Possibles}
\begin{itemize}
    \item \textbf{Feature Selection} : Avec 590 features et 1567 échantillons ($p \gg n$), une sélection de variables (PCA, importance des features, LASSO) pourrait améliorer la généralisation.
    \item \textbf{Autres techniques de rééchantillonnage} : ADASYN, BorderlineSMOTE, ou combinaison SMOTE + sous-échantillonnage (SMOTETomek).
    \item \textbf{Modèles supplémentaires} : XGBoost, LightGBM avec gestion native du déséquilibre via \texttt{scale\_pos\_weight}.
    \item \textbf{Cost-sensitive learning} : Assigner des poids de classe (\texttt{class\_weight='balanced'}) comme alternative à SMOTE.
\end{itemize}

% ══════════════════════════════════════════════════════════════
%                      6. CONCLUSION
% ══════════════════════════════════════════════════════════════
\section{Conclusion}

Ce projet a permis de comparer quatre modèles de classification sur le dataset SECOM, en mettant l'accent sur la gestion rigoureuse du déséquilibre de classes.

\textbf{Résultats clés} :
\begin{itemize}
    \item \textbf{AdaBoost} est le meilleur modèle au seuil par défaut (Score composite = 0.4367 en Approche A), grâce à son meilleur compromis AUC/Recall/F1.
    \item \textbf{L'optimisation des hyperparamètres} améliore le Recall de tous les modèles. AdaBoost optimisé atteint \textbf{64.5\%} de Recall (+150\%) avec un learning rate de 0.04.
    \item \textbf{SMOTE est indispensable} : sans rééchantillonnage, le Recall total chute de 0.29. AdaBoost passe de 25.8\% (SMOTE) à seulement 3.2\% (sans SMOTE).
    \item \textbf{Random Forest} a le meilleur AUC (0.83) mais nécessite une optimisation du seuil (0.18 au lieu de 0.5) pour détecter les défauts.
    \item \textbf{Le data leakage} (Approche B) surestime les performances de +8 à 9\% : les résultats ne sont pas fiables en production.
    \item Le \textbf{Recall} est la métrique prioritaire en détection de défauts industriels : mieux vaut quelques faux positifs que des défauts non détectés.
\end{itemize}
